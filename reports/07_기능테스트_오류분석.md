**T-10 상세**
- worker 중지 상태에서도 web은 202로 접수 (job 14)
- 5초 뒤 `status: queued`, 결과 필드 모두 null → 처리할 worker 없음
- `docker compose start worker` 10초 뒤 같은 job 14가 `done` → Redis 브로커에 남아 있던 메시지를 재시작한 worker가 처리
- 이때 `cache_hit: true` → 직전 성능 측정에서 같은 사진 결과가 캐시(600초)에 남아 있었음
- 이번에는 재시작 후 처리됐지만, **항상 기존 작업이 처리된다고 보장하지는 않음**
